# 游标逐刻线校正诊断状态设计

## 目标

使逐刻线校正诊断与正式游标候选一一对应。每个正式候选都必须在诊断结果中出现，即使它不能被连续细笔画追踪。

## 范围与约束

只在 `make_debug=True` 的详细模式新增诊断状态，不改变正式投影候选、连通域证据、谷底选择、零线、刻线数量或读数。

不补线、不拟合理论刻线网格，也不将未追踪候选从正式结果删除。

## 数据结构

逐刻线拉直函数保留现有默认返回值，以兼容已有调用；详细模式额外请求 `candidate_states`。每个状态记录至少包含：

- `approx_x`：正式投影候选位置；
- `status`：`traced` 或 `untraced`；
- `reason`：成功时为空；失败时为 `no_top_thin_seed` 或 `insufficient_continuous_thin_height`；
- 成功时保留轨迹的接缝参考位置和追踪纵向范围。

`traced` 候选才写入独立拉直后的刻线带；`untraced` 候选不写入拉直带，但仍显示在原始带叠加图、状态统计和候选列表中。

## 验证

新增单元测试构造一条可追踪细线与一个无法追踪的候选，断言状态数等于输入候选数、两种状态都出现、未追踪候选带有原因。集成测试断言详细模式中 `trace_count + untraced_count == candidate_count`，并继续保证详细模式不改变零线或读数。
