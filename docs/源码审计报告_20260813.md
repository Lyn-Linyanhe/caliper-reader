# 游标卡尺项目源码审计报告

审计日期：2026-08-13

审计目标：以当前工作区源码为准，确认正式识别调用链、标准化与校正研究路径、已删除旧路径、配置字段读取状态和当前批量评估基线。本文不把离线脚本或旧设计文档误认为正式运行代码，也不对正式读数写入文件名真值。

## 1. 正式调用链

```text
main.py / read_caliper()
  -> CaliperPipeline.run()
      -> locate_roi_lowres()
      -> preprocess()
      -> orient_caliper()
      -> split_scales()
      -> recognize_main_scale()
      -> recognize_vernier_scale()
      -> merge_readings()
      -> CaliperResult
```

`CaliperPipeline.run()` 每次运行都会清空实例上的 `debug_images`、`step_results` 和 `timings`。首次游标识别只有在返回 `no_reliable_valley_bounded_tick_range` 且 ROI 提供局部扩边候选时，才会按候选重复后续流程；正常样本不会因为详细模式而改变正式读数。

### 1.1 各阶段职责

| 阶段 | 实现 | 正式输出 |
| --- | --- | --- |
| ROI | `caliper/roi_extract.py::locate_roi_lowres` | 原图 ROI 框、ROI 来源、候选和局部恢复候选 |
| 预处理 | `caliper/preprocess.py::preprocess` | 增强灰度图、统一二值图 |
| 方向校正 | `caliper/roi_extract.py::orient_caliper` | 接缝 Scharr 响应、RANSAC 角度、旋转后的彩色/灰度/二值图 |
| 区域分离 | `caliper/region_split.py::split_scales` | `split_y`、主尺/游标区域、两套 `tick_band` |
| 主尺刻线 | `caliper/main_scale.py::recognize_main_scale` | 实测主尺刻线、`x_precise`、`main_gap`；`main_digits` 为空 |
| 游标刻线 | `caliper/vernier_scale.py::recognize_vernier_scale` | 谷底范围、实测游标刻线、`zero_x`、对齐候选和小数读数 |
| OCR/合并 | `caliper/merger.py::merge_readings` | 定向主尺 OCR、整数推导、总读数和最终标注 |

主尺 OCR 不在 `main_scale.py` 中执行，因为 OCR 候选框必须使用游标 `zero_x` 限制到正确一侧；正式入口是 `merger.py` 的 `_compute_main_reading_with_info()`。

## 2. 正式结果约束

```text
total = main_scale + vernier_scale
vernier_scale = best_index * 0.02
```

正式游标小数是离散的 `0.02 mm` 网格值。`x_precise` 只用于比较已观察刻线的横向接近程度；`continuous_index` 是对齐曲线的诊断插值，不能乘以 0.02 写回正式读数。文件名仅由离线评估脚本作为真值来源，不能参与生产识别。

## 3. 必须保留的研究路径

以下入口没有合并进正式读数，但都具有明确的后续研究用途，不能按“当前不可达”删除。

| 入口 | 当前触发位置 | 研究用途 | 当前边界 |
| --- | --- | --- | --- |
| `main_scale._standardize_tick_response` | 详细主尺刻线图 | 用接缝附近真实前景支持生成主尺观测响应 | 不生成缺失主尺线，不修改正式刻线 |
| `vernier_scale._build_length_clustered_standard_response` | 详细游标刻线图 | 对已接受游标刻线的实测长度做一维两类聚类，显示短/长结构 | 不强制 51 条，不补线，不参与零线或小数 |
| `vernier_scale._component_bottom_response` | 详细游标面板 | 显示匹配连通域的下端位置响应 | 仅诊断 |
| `vernier_scale._trace_vernier_tick_centerline` | 逐刻线校正诊断 | 从接缝侧独立追踪每条细刻线，允许每条线有不同斜率 | 不回写正式 `vernier_ticks` |
| `vernier_scale._build_per_tick_straightened_band` | 逐刻线校正诊断 | 将各自有效轨迹独立拉直后进行显示比较 | 不替换正式投影或对齐 |
| `vernier_rectify.rectify_vernier_region` | 公共研究接口 | 整块游标区域的未来裁剪/几何校正 | 当前流水线只使用 `_find_vernier_body_x_range` 辅助 ROI |
| `utils.refine_ticks_by_spacing` | 显式研究调用 | 在邻近列确有前景证据时做候选去重、补全和网格吸附实验 | 正式主尺/游标流程均不调用 |

研究路径依赖的游标字段包括 `x_projection`、`x_refined`、`x_precise`、`length`、`component_id`、`component_height`、`component_bottom_y`、`x_top`、`x_bottom`、`fit_slope`、`is_long` 和 `long_state`。删除或改名这些字段前必须先更新研究接口、契约测试和详细可视化。

## 4. 详细模式与快速模式边界

`fast_mode=False` 才生成谷底曲线、连通域响应、长度聚类标准曲线和逐刻线校正面板。它们从正式检测已经接受的候选生成，只读不写，不改变 `vernier_ticks`、`zero_x`、`vernier_reading`、`total`。回归测试已比较快速/详细模式的总读数和零线。

## 6. 配置读取结论

### 当前正式或条件生效

- 预处理：gamma、双边滤波、中值滤波、CLAHE、锐化、自适应阈值，以及显式开启的开运算/连通域过滤。
- ROI：中心/投影框比例、边界余量、最小尺寸；主体精修和紧凑结构验证由源码内规则完成。
- 方向：只有 `angle_detection_scale` 生效；正式方向算法是 Scharr-y + RANSAC，而不是 Hough。
- 区域分离：竖直开运算、细长组件尺寸、组件端点优先级、投影平滑和游标最小高度。
- 主尺：投影阈值、最小刻线数、长线辅助规则、短线连续前景恢复。
- 游标：谷底评分、两侧峰支撑、内部断裂、候选去重、连通域桥接/开运算、长度聚类分离度、对齐置信度和歧义阈值。
- OCR：定向标签组合间距、patch 放大/增强，以及实际选中的 Tesseract/EasyOCR 引擎参数。

### 保留但当前正式路径不读取

- ROI 轮廓评分、轮廓权重和形态学闭运算字段。
- OrientConfig 中的 Canny、Hough、角度范围、旋转阈值字段。
- RegionSplitConfig 中的旧搜索范围、density、CLAHE、闭运算和梯度字段。
- MainScaleConfig 的 `peak_min_dist` 和 `spacing_*` 字段；间距工具本身仍保留为研究接口。
- OCRConfig 中旧全扫描投影、搜索、连通域合并和回退字段；正式定向连通域阈值位于 `main_scale.find_digit_cc_candidates()`。
- MergerConfig 全部字段；当前合并置信度与绘图颜色仍由 `merger.py` 内部逻辑控制。

修改“保留/未读”字段不会改变当前结果，调参前必须先查实际读取点。历史字段只有在新研究分支明确接入并有回归测试后才应重新启用。
