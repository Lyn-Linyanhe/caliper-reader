# 游标卡尺读数识别项目代码说明书

本文档面向后续维护、调参、复现实验和定位错误的开发者。内容以当前工作区中由 CaliperPipeline.run() 实际调用的源码为准。模块头部的历史注释、旧设计文档、论文材料或 UI 文案与正式行为不一致时，应优先相信本说明书列出的调用链及其对应源码。

本项目面向分度值为 0.02 mm 的游标卡尺照片。正式识别不读取图片文件名推断读数，不按理论等距网格补造刻线，也不强制把游标刻线拟合成固定的 51 条。图片文件名只在离线测试中作为真值来源。

## 1. 系统目标与结果边界

### 1.1 正式读数

一次正常识别的正式数值关系如下。

~~~text
total = main_scale + vernier_scale
precision = 0.02 mm
~~~

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| main_scale | 主尺整数毫米部分 | 主尺 OCR 标签与游标零线的相对刻线位置。 |
| vernier_scale | 游标小数部分 | 已观测游标刻线中，与最近主尺刻线横向误差最小的离散索引乘以 0.02 mm。 |
| total | 程序正式输出 | main_scale 与 vernier_scale 之和。 |
| precision | 当前仪器分度制式 | 代码固定为 0.02 mm。 |
| confidence | 内部结构质量提示 | 主尺/游标刻线数量和主尺间距稳定性；不是经标定的准确率或误差上限。 |

以下信息只能用于诊断或人工复核，不能覆盖 total。

| 信息 | 正确用途 | 禁止用途 |
| --- | --- | --- |
| continuous_index | 观察最佳游标对齐附近的误差曲线是否平坦。 | 乘以 0.02 后写回小数读数；那会产生 0.03 mm 等非分度值。 |
| alignment_ambiguity.reference_total | 最优游标线和相邻游标线误差接近时的参考读数。 | 自动替换正式读数。 |
| 游标长度聚类标准曲线 | 详细模式中检查长短刻线结构。 | 补线、修正零线或参与正式小数读数。 |
| 单刻线追踪/拉直图 | 详细模式中分析单条倾斜刻线。 | 回写正式刻线位置、零线或对齐结果。 |
| 图片文件名 | 批评估的真值。 | 在生产识别中修正 OCR 或读数。 |

### 1.2 可信结果的证据链

一个可复核的读数应能顺着下列链路逐项找到图像证据。

~~~text
ROI 覆盖数字、主尺、游标和接缝
  -> 主尺/游标分割线没有截短两套刻线
  -> 主尺刻线与 main_gap 合理
  -> 两侧谷底夹住完整游标刻线范围
  -> 范围内第一条真实刻线是游标零线
  -> OCR 数字绑定到正确的主尺刻线
  -> 某条实际游标刻线与主尺刻线最接近
  -> main_scale + vernier_scale = total
~~~

其中任一环节没有图像证据时，都不应以文件名、理论网格、固定刻线数量或人工期望值补上。

### 1.3 支持范围和当前限制

- 输入是一张包含游标卡尺的 BGR 彩色图。GUI 可选 JPG、JPEG、PNG、BMP 和 TIFF。
- 当前小数读数固定为 0.02 mm 网格，代码没有自动判断 0.05 mm、0.1 mm 等其他游标制式。
- 当前多位主尺标签只组合 10 到 15：左字符必须为 1，右字符为一位数字，且二者足够接近。
- 强反光、严重模糊、数字与刻线大面积连通、ROI 漏掉有效结构、接缝不清晰时，程序可能给出错误候选。非零输出不等于无需人工复核。
- 当 OCR 无法获得主尺整数时，主尺部分会返回 0.0；最终总数可能因此只留下游标小数，不能当作完整测量结果。

### 2.3 Python API

~~~python
import cv2
from caliper import CaliperPipeline, read_caliper, read_caliper_from_array

# 路径入口内部使用 np.fromfile + cv2.imdecode，可处理常见中文路径。
result = read_caliper(r"tupian\72.52.jpg")
print(result.total, result.precision)

# 已有 OpenCV BGR ndarray 时。
image = cv2.imread(r"tupian\72.52.jpg")
result = read_caliper_from_array(image)

# 需要中间状态、计时或详细图时保留 Pipeline 实例。
pipeline = CaliperPipeline(fast_mode=False)
result = pipeline.run(image)
print(pipeline.step_results.keys())
print(pipeline.timings)
~~~

| API | 输入 | 输出/行为 |
| --- | --- | --- |
| read_caliper(image_path) | 图片路径字符串 | 返回 CaliperResult；无法读图时抛出 FileNotFoundError。 |
| read_caliper_from_array(img) | OpenCV BGR numpy.ndarray | 返回 CaliperResult。 |
| CaliperPipeline(fast_mode=False).run(img, progress_callback=None) | BGR 图像和可选进度回调 | 返回 CaliperResult，并在实例上保存 debug_images、step_results、timings。 |

每次调用 run() 都会清空该 Pipeline 实例之前保存的阶段结果。progress_callback 的签名为 progress_callback(step_key, image, status)；GUI 用它在后台识别期间逐步展示调试图。

### 2.4 输出数据契约

caliper/result.py 定义：

~~~text
TickInfo(x, y_start, y_end, y_mid, length, is_long)
DigitInfo(x, y, value, text, confidence, bbox)
CaliperResult(main_scale, vernier_scale, total, precision, confidence,
              image_annotated, debug_images, extra_info)
~~~

正式流水线中的刻线结果目前以字典列表而非 TickInfo 实例传递。常见字段如下。

| 对象 | 常见字段 | 坐标说明 |
| --- | --- | --- |
| 主尺刻线 | x、x_projection、x_precise、y_start、y_end、length、is_long | x 位于旋转后 ROI；y 是主尺局部坐标。 |
| 游标刻线 | 主尺字段及 x_refined、component_id、component_area、component_height、source | x/x_precise 已映射到旋转后 ROI；y 是游标局部坐标。 |
| ROI 结果 | roi_box_original、roi_source、roi_selection | roi_box_original=(x1,y1,x2,y2) 位于输入全图，右下边界为切片终点。 |
| 区域分离 | split_y、region_main、region_vernier、tick_bands、seam_source | split_y 位于旋转后 ROI；游标全局 y 为局部 y 加 split_y。 |

extra_info 是诊断扩展字典，不应被视为不变的外部 API。正常结果一般含 main_ticks_count、vernier_ticks_count、main_gap_px、zero_x、main_derivation、alignment_ambiguity 和 timings；ROI 失败结果只保证保留错误文本和已有耗时。

## 3. 坐标、二值极性与精度约定

### 3.1 坐标层级

~~~text
输入全图 (X, Y)
  -> 原图 ROI 框 roi_box_original
  -> 裁剪并旋转后的 ROI (x, y)
      -> 主尺区域：y 使用主尺局部坐标
      -> 游标区域：局部 y = ROI y - split_y
      -> 游标窄刻线带：再减 band_y1
~~~

主尺和游标的最终横坐标必须映射到同一张旋转 ROI 的 x 轴，才可以直接比较对齐误差。不要把原图坐标、未旋转 ROI 坐标和旋转后 ROI 坐标混用。

### 3.2 二值图极性

preprocess() 的 binary_adaptive 使用 cv2.THRESH_BINARY，通常为黑色刻线/数字、白色背景。区域分离、主尺和游标模块在检测前会通过 _foreground_binary_from_region() 或等效逻辑转换为“前景为正值/白色”的掩码。因此，调试图视觉上的黑白不一定等于内部投影使用的极性；分析投影前应先确认对应函数的前景规范化步骤。

### 3.3 亚像素位置不会产生连续分度

utils.refine_tick_x_subpixel() 在灰度小窗口中找暗刻线两侧边缘，以边缘中心的中位数形成 x_precise。它提高“哪条线最接近”的稳定性，但不改变游标的离散物理分度。

~~~text
vernier_scale = best_index * 0.02
~~~

continuous_index 是最佳误差位置附近的抛物线插值结果，仅供诊断，不改变 best_index、aligned_tick 或 vernier_scale。

## 4. 实际调用链

### 4.1 完整顺序

~~~text
main.py 或 read_caliper()
  -> CaliperPipeline.run()
      -> locate_roi_lowres()
      -> preprocess()
      -> orient_caliper()
      -> split_scales()
      -> recognize_main_scale()
      -> recognize_vernier_scale()
      -> merge_readings()
      -> CaliperResult
~~~

CaliperPipeline.run() 先执行一次完整链路。只有首次游标识别报 no_reliable_valley_bounded_tick_range 且 ROI 预先提供了小幅扩边候选时，才会对这些局部候选重复后续流程。其余正常样本不会因恢复逻辑重新选择 ROI。

### 4.2 阶段结果位置

| step_results 键 | 由谁写入 | 主要内容 |
| --- | --- | --- |
| roi | locate_roi_lowres() | ROI 图像、原图框、来源、候选选择诊断和恢复候选。 |
| preprocess | preprocess() | 增强灰度、二值图、中间图和步骤耗时。 |
| orient | orient_caliper() | 旋转后的彩色/灰度/二值图、角度和接缝拟合诊断。 |
| split | split_scales() | split_y、两区域、刻线带、接缝来源。 |
| main | recognize_main_scale() | 主尺刻线、main_gap、主尺刻线图。 |
| vernier | recognize_vernier_scale() | 游标刻线、零线、谷底诊断、对齐和错误原因。 |
| timings | Pipeline | 各阶段和部分子阶段的毫秒耗时。 |

正式读数的关键中间量不全部位于 step_results：OCR 选择与主尺整数推导位于 result.extra_info 的 main_derivation，对齐歧义的总读数位于 alignment_ambiguity。

### 4.4 研究路径保留边界

以下代码目前不改变正式读数，但必须保留，因为它们对应后续标准化曲线、刻线校正和方向校正研究：

| 研究入口 | 当前用途 | 当前边界 |
| --- | --- | --- |
| `main_scale._standardize_tick_response()` | 将已检测主尺刻线按图像支持归一为显示响应 | 只生成诊断响应，不补造正式主尺刻线。 |
| `vernier_scale._build_length_clustered_standard_response()` | 按观测刻线长度聚类，显示短线 1.0、长线 1.5 的标准曲线 | 不强制 51 条、不生成理论缺线、不参与零线或小数对齐。 |
| `vernier_scale._trace_vernier_tick_centerline()`、`_build_per_tick_straightened_band()` | 对每条游标刻线独立追踪并拉直，允许每条线不同斜率 | 仅详细模式诊断；不回写 `vernier_ticks`、`zero_x` 或 `total`。 |
| `vernier_rectify.rectify_vernier_region()` | 整个游标主体的未来裁剪/校正接口 | 当前流水线只使用主体 x 范围辅助函数，整块结果未接入。 |
| `utils.refine_ticks_by_spacing()` | 显式研究等间距候选补全、去重和网格吸附 | 只有附近列存在前景支持时才接受候选；正式主尺和游标流程均不调用。 |

研究路径的修改必须满足两条：一是有独立测试证明输出结构和图像证据仍有效；二是快速/详细正式读数回归不发生变化。研究代码不能因为尚未接入正式流程而被当作普通遗留代码删除。

#### 4.4.1 标准化/校正路径的依赖链

“标准化曲线尚未参与正式读数”不等于“曲线代码可以单独删除”。曲线依赖
正式刻线阶段产生的几何字段、游标连通域响应和逐线轨迹；删除其中任一项会
使后续研究失去可复现的输入。当前依赖关系如下。

| 研究结果 | 生成入口 | 直接依赖 | 当前触发条件 | 后续可研究方向 |
| --- | --- | --- | --- | --- |
| 主尺标准化响应 | `main_scale._standardize_tick_response()` | `_seam_anchored_support()`、已接受主尺候选的 `x_projection` | 详细模式绘制 `3a_主尺刻度线` | 用真实接缝支撑比较长短主尺线，研究长度归一化或刻线质量评分。 |
| 游标长度聚类标准曲线 | `vernier_scale._build_length_clustered_standard_response()` | 已接受游标刻线的 `x_projection`、`length` | 详细模式绘制 `4b_游标刻度线` | 用观测长度聚类改善长短线分类，不能直接生成缺失刻线。 |
| 游标连通域下端响应 | `vernier_scale._component_bottom_response()` | `component_id`、`component_bottom_y`、游标候选 x | 游标详细面板 | 研究倾斜刻线的下端位置、组件支持和候选质量。 |
| 单刻线中心线与拉直响应 | `_trace_vernier_tick_centerline()`、`_build_per_tick_straightened_band()` | 原始游标带、候选 `x_projection`、实测 `observed_period` | 详细模式的逐刻线诊断面板 | 对每条刻线独立估计斜率，未来再评估是否接入校正后的投影/对齐。 |
| 游标主体裁剪/校正 | `vernier_rectify.rectify_vernier_region()` | 游标区域灰度/二值图、`_find_vernier_body_x_range()` | 当前公共研究接口未由 Pipeline 调用 | 整块游标区域的几何校正或更紧主体裁剪。 |
| 显式间距精修 | `utils.refine_ticks_by_spacing()` | 候选 x、二值图中的邻近前景支持 | 仅显式研究调用 | 在有图像支持时做去重、补全和网格吸附；不得变成无证据补线。 |

#### 4.4.2 必须保留的刻线字段契约

下列字段不是冗余元数据，而是标准化曲线、逐线校正和后续对齐研究的输入。
字段缺失时应先更新测试和研究接口，不应直接删掉或改名。

| 字段 | 所属 | 当前用途 | 后续研究用途 |
| --- | --- | --- | --- |
| `x_projection` | 主尺/游标 | 投影候选的离散 x，绘制标准化峰和记录原始候选。 | 比较投影中心与精细化中心的偏移。 |
| `x_refined` | 主尺/游标 | 连通域或局部细笔画精修后的 x 初值。 | 作为逐线几何校正的初始锚点。 |
| `x_precise` | 主尺/游标 | 灰度边缘亚像素 x；正式游标对齐使用该值。 | 评估校正前后亚像素位置变化。 |
| `length` | 主尺/游标 | 实测前景长度；主尺长线恢复和游标长度聚类读取。 | 长短线聚类、长度归一化和异常线检测。 |
| `component_id`、`component_height`、`component_bottom_y` | 游标 | 连通域匹配、候选支持和下端响应曲线。 | 区分刻线与数字粘连、追踪下端和组件拆分。 |
| `x_top`、`x_bottom`、`fit_slope` | 游标 | 保存刻线顶部/底部位置及局部斜率；当前不回写正式对齐。 | 每条刻线独立拉直、透视补偿和校正后投影。 |
| `is_long`、`long_state` | 主尺/游标 | 详细图和主尺 OCR 长线锚点；游标分类不稳定时可为 `unknown`。 | 结合聚类结果和周期结构改进长短线判定。 |

这些字段与标准化曲线的关系是“观测输入 -> 诊断输出”，不是“诊断输出 ->
正式读数”。当前任何标准化或逐线校正结果都不能回写 `vernier_ticks`、
`zero_x`、`vernier_reading` 或 `total`；未来接入时必须增加独立开关、输入输出
契约和快速/详细回归对照。

## 5. 图像与几何阶段

### 5.1 ROI 定位：locate_roi_lowres()

正式入口为 caliper/roi_extract.py 的 locate_roi_lowres()，不是螺丝模板匹配。该函数默认先把输入全图缩小到最大宽度 1600，然后在低清图中定位读数区域。

执行步骤如下。

1. 全图转灰度，按 config.preprocess.gamma 做幂律变换，再以固定 clipLimit=1.0、8x8 的 CLAHE 增强低清灰度图。
2. 自适应二值化的块大小由 min(height,width)/18 推得并截断在 15..51 的奇数范围，常数为 C=9；取反后得到低清前景。
3. y 方向对前景逐行投影，以加权质心为中心，使用 roi.y_center_span_ratio 构造初框，再以 roi.y_pad_ratio 扩边。
4. x 方向在该 y 带内做投影。先检测强峰，估计实测刻线间距，再寻找最长的近似等间距强峰序列。相邻间距允许在估计间距的 0.50..1.80 倍之间，最多容忍连续两次不规则间隔。
5. 由最长序列两端加保护边距得到投影框；随后利用游标压块灰度结构收窄 x 范围，再以卡尺金属面的上下边缘和游标压块右缘细化主体框。
6. 在 projection -> body -> compact 三层候选中选择。紧凑框只有通过 _reading_roi_preserves_structure() 的检查才会使用：检查裁剪尺寸、投影得到的左侧主尺参考是否仍被保留，以及竖直开运算后的行支持是否仍存在。它并不逐条验证主尺与游标尺都已完整保留；验证失败则退回主体框，再不行退回投影框。
7. 低清框映射回原图。x 方向增加至少 30 px 或 ROI 宽度 1.5% 的安全边界；y 方向增加至少 15 px 或 ROI 高度 4% 的安全边界。

roi_source 通常为 lowres_compact 或 lowres_body。历史螺丝模板匹配入口已从当前源码删除；不能把旧设计记录或旧调试目录当作当前 ROI 结果的解释。

### 5.2 局部 ROI 扩边恢复

Pipeline 的直接触发条件如下。

~~~text
首次游标错误 == no_reliable_valley_bounded_tick_range
且 roi_recovery_candidates 非空
~~~

当前 locate_roi_lowres() 只会在选中 compact 候选时生成 roi_recovery_candidates，因此就当前实现而言，这等价于“首次采用紧凑 ROI 且游标范围未能可靠建立”。这里是候选列表的生成约束，不是 Pipeline.run() 中额外写出的 ROI 来源判断。

候选只在主体框范围内对紧凑框横向扩边：左 1/3、左 2/3、右 1/3、右 2/3、左右各 1/3。不会回退到明显更大的全主体框。

恢复候选只有满足以下条件才接纳。

~~~text
vernier.error 为空
len(vernier_ticks) >= max(min_tick_count, recovery_min_observed_tick_count)
zero_x > 0
~~~

当前 recovery_min_observed_tick_count=40。所有尝试失败时，Pipeline 恢复首次结果，并在 result.extra_info 的 roi_recovery 中保留候选名称、面积增量、游标错误、刻线数和零线等信息。

### 5.3 预处理：preprocess()

实现位于 caliper/preprocess.py。

~~~text
BGR -> 灰度 -> gamma -> 双边滤波 -> 可选中值滤波
    -> CLAHE -> 非锐化掩膜 -> 自适应二值化
    -> 可选开运算 -> 可选小连通域过滤
~~~

| 参数 | 默认值 | 实际作用 |
| --- | ---: | --- |
| gamma | 1.5 | 使用 s=255*(r/255)^(1/gamma)。按这条实际公式，gamma 大于 1 会抬高 0 到 255 之间的像素值，例如 64 大约变为 101，因此实际效果是提亮中间调；gamma 小于 1 则压暗中间调。 |
| bilateral_d / bilateral_sigma | 5 / 25 | 保边的轻量去噪。 |
| median_ksize | 0 | 小于 3 时跳过中值滤波。 |
| clahe_clip_limit / tile | 1.0 / 8x8 | 局部对比度增强。 |
| unsharp_amount / sigma | 0.25 / 1.5 | 非锐化掩膜：enhanced + amount*(enhanced-blur)。 |
| adaptive_block_size / adaptive_C | 91 / 17 | 正式自适应阈值参数。 |
| adaptive_binary_scale | 0.8 | 先在 80% 尺寸二值化，再最近邻放大。 |
| morph_open_enabled / cc_filter_enabled | False / False | 默认不做全局开运算和全图小连通域过滤。 |

CaliperPipeline 的构造函数会缓存 gamma、双边滤波参数、median_ksize 和 CLAHE clip limit。因此在构造 Pipeline 后再修改这些配置，不会影响该实例的预处理；其他预处理配置由 preprocess() 运行时读取。

### 5.4 全局方向校正：orient_caliper()

方向校正只消除整体拍摄倾斜，不会将每一条游标刻线分别拉直。实际算法是接缝梯度加 RANSAC，不是旧注释中的 Canny/Hough。

1. 按 orient.angle_detection_scale，默认 0.75，缩小图像，仅在缩小图上估计角度。
2. 先调用 `_analyze_horizontal_tick_bands()` 得到刻线带投影，再用 `_split_from_tick_band_valley(band_info)` 取谷底中的动态种子；随后追加 0.58H、0.64H、0.70H 三个固定高度候选，并将相距不超过 15 px 的候选去重。固定候选是动态估计失败时的兜底，不是对动态结果的替代。
3. 在每个种子附近取水平带，对灰度图做 Scharr y 向梯度和横向平滑；从多个 x 位置收集局部峰点。
4. 用 RANSAC 排除离群点，再做加权直线拟合。高质量候选需要足够保留点、横向覆盖、较小残差中位绝对偏差和合理角度。
5. 若没有有效接缝或角度绝对值超过 2 度，角度回退为 0 度；否则用该角度同时旋转彩色、灰度和二值 ROI。

旋转采用扩展画布、白色边界填充。后续主尺、游标、OCR 都在旋转后的坐标系中工作。OrientConfig 的 Canny、Hough、角度筛选和旋转阈值字段没有进入这条正式路径。

### 5.5 区域分离与刻线带：split_scales()

区域分离沿 y 轴确定主尺和游标之间的 split_y。正式优先级为：

~~~text
细长竖直连通域的主尺末端/游标起端响应
  -> 水平刻线带之间的投影谷底
  -> 固定物理比例 0.60H
~~~

具体步骤：

1. 对前景二值图做竖直开运算，核高约为 0.032H，再截断到 35..61 px；若结构太少则回退原前景。
2. 筛选窄且足够高的竖直组件。默认宽度上限约为 0.0025W 并截断到 8..14 px，高度上限为 0.22H。
3. 累积组件起点和终点的 y 响应。在 0.34H..0.75H 内寻找接近的主尺末端峰和游标起端峰，允许的间距约为 24..36 px。
4. 端点候选分数低于 0.18 时不采用。成功时 split_y 取主尺末端 y；与两个端点接近的组件进一步形成主尺和游标的 tick_band。
5. 端点证据不足时，从水平刻线带的谷底中取最低响应；仍失败时采用 fallback_split_ratio=0.60。
6. 最终保证游标区域高度至少为 ROI 的 min_vernier_height_ratio=0.28。

tick_band 是后续刻线检测真正使用的纵向带，不是整个主尺或游标区域。分割线偏上会截短主尺刻线及 OCR 锚点；偏下会把主尺结构混入游标，两种错误都会向后传播。

## 6. 主尺刻线与整数读数

### 6.1 主尺刻线：recognize_main_scale()

实现位于 caliper/main_scale.py。该模块当前只负责观察主尺刻线、估计 main_gap 和提供 OCR 的几何锚点；正式 OCR 不在这里执行。

处理流程如下。

1. 读取 region_main 的 image、binary 和 tick_band。若上游二值图无效、尺寸不符或前景过少，使用 MainScaleConfig 的自适应阈值重建二值图；若仍前景不足，回退 Otsu。
2. 仅在 tick_band 内按列统计前景，得到归一化垂直投影。
3. 以投影均值加 peak_threshold_factor 倍标准差作为阈值，最低阈值为 0.02。默认 peak_threshold_factor=0.20。每段连续超阈响应的中心作为粗候选 x。
4. 对每个粗候选，在附近 7 像素宽的二值竖条中找最长连续前景段。正常最小长度为刻线带高度的 25%，且不低于 6 px。
5. 对靠近分割线、被刻线带裁短的真实主尺线，允许短线恢复。候选必须同时满足连续长度不低于最小长度的 60%、前景量足够，并且左右候选间隔都在实测周期的 30% 容差内。
6. 先从二值竖条中选择最密的刻线中心，再在灰度图的接缝附近参考 y 带中做 x_precise 亚像素精修。
7. 对已确认候选，在完整主尺二值图中仅向与它相连的上方前景恢复可见长度。恢复后的长度重新参与长刻线判断。
8. 对过近候选按相对间距 0.45 去重，保留投影强度、组件面积和长度更优者。最终 main_gap 是主尺 x 差的中位数。

主尺刻线使用的核心默认参数如下。

| 参数 | 默认值 | 正式含义 |
| --- | ---: | --- |
| peak_threshold_factor | 0.20 | 主尺投影超阈候选的标准差系数。 |
| min_tick_count | 3 | 少于该数量时直接返回空主尺结果。 |
| long_tick_factor | 1.30 | 长度大于中位长度 1.30 倍时标为长刻线。 |
| short_tick_recovery_enabled | True | 是否允许受分割裁切的短线恢复。 |
| short_tick_min_contiguous_ratio | 0.60 | 短线恢复所需最小连续长度比例。 |
| short_tick_min_foreground_factor | 2.00 | 短线恢复所需前景量比例。 |
| short_tick_period_tolerance | 0.30 | 短线恢复的左右周期相对容差。 |

重要边界如下。

- 这一步恢复的是已有候选的连续可见前景长度，不是在缺口处创建新主尺刻线。
- main_result 的 main_digits 在当前正式流程中故意为空；OCR 已迁移到 merger.py，因为 OCR 框必须依赖后续得到的游标 zero_x。
- config.main_scale 中的 peak_min_dist 和全部 spacing_* 参数目前没有被该正式流程读取。历史的 spacing 补全入口已删除；当前流程不会用等间距网格补造主尺刻线。

### 6.2 OCR 候选框：find_nearest_cm_digit_region()

正式 OCR 框并非在全主尺扫描，而是在游标 zero_x 已知以后定向裁剪。设主尺间距为 g=main_gap，主尺 OCR 锚点为 y_top_tick，首次框为：

~~~text
y_top    = y_top_tick - 4g
y_bottom = y_top_tick - 1g
x_left   = zero_x - 1.7 * (10g)
x_right  = zero_x + 0.4 * (10g)
~~~

常规 y_top_tick 是全体主尺刻线 y_start 的 85 百分位，用来贴近普通主尺刻线顶部。若启用 prefer_long_ticks，则在至少三条长线存在时改用长线 y_start 的 25 百分位，优先观察恢复后的长刻线上沿。

当前 OCR 的重试顺序仅在“有候选框但没有数字连通域或没有 OCR 数字”时触发：

~~~text
常规锚点、上下不扩展
  -> 上下各扩展 1 * main_gap
  -> 长刻线锚点、上下不扩展
~~~

如果一开始就无法生成候选框，例如 zero_x 小于等于零、main_gap 小于等于零或主尺刻线为空，则直接报告缺少输入或无数字区域，不会盲目扩大整张主尺。

### 6.3 数字连通域与 OCR 引擎

find_digit_cc_candidates() 在 OCR 裁剪图中找可能的单字符连通域。当前实际筛选逻辑的一部分直接写在 main_scale.py 中：

| 约束 | 当前值/规则 |
| --- | --- |
| 面积下限 | min(700, max(250, 0.09 * OCR 框高度平方))。 |
| 面积上限 | max(3000, 0.20 * OCR 框高度平方)。 |
| 最小尺寸 | 宽至少 3 px，高至少 5 px。 |
| 高宽比 | height / width 在 0.6 到 3.5。 |
| 位置评分 | 面积、长宽比与垂直位置的组合，仅供候选质量。 |

每个单字符 patch 由 DigitReader.ocr_patch_to_digit() 识别。引擎初始化优先级为：

~~~text
有效模板目录
  -> Tesseract
  -> EasyOCR
  -> fallback（无 OCR 引擎）
~~~

模板识别会把字符规范化到 32x48，比较前景 IoU 与零均值相关系数的加权得分：

~~~text
template_score = 0.65 * IoU + 0.35 * max(0, correlation)
~~~

低于 0.38 的模板结果被拒绝。Tesseract 和 EasyOCR 都只接受数字字符。fallback 状态不会为当前定向 OCR 根据位置猜数字，因此正常 OCR 失败会使主尺读数为 0.0。

### 6.4 标签分组、绑定与主尺整数公式

OCR 得到的单字符按 x 排序。仅满足以下条件才将相邻两个字符合成多位数：

~~~text
左字符值 == 1
0 <= 两字符外框横向间隙 <= max(6 px, 0.75 * main_gap)
组合值在 [10, 15]
~~~

单字符或组合后的标签中心必须绑定到距离不超过 max(8 px, 0.45 * main_gap) 的主尺刻线。随后选择主尺标签：

1. 优先选择零线左侧最近的已绑定标签。
2. 若左侧没有标签，而零线右侧一个主尺间距内有数值大于 0 的标签，则使用这个标签的数值减 1。
3. 统计标签参考刻线与 zero_x 之间的主尺刻线数。

正式主尺整数计算为：

~~~text
main_scale = 10 * selected_label_value + ticks_between_label_and_zero
~~~

计数时不重复计入标签自己的参考刻线，允许 zero_x 与主尺刻线有小的亚像素对齐误差。相关信息保存在 result.extra_info 的 main_derivation 中，常见字段包括：

| 字段 | 意义 |
| --- | --- |
| strategy | 成功时为 ocr，失败时为 ocr_failed。 |
| ocr_text / ocr_confidence / ocr_engine | 选中标签的文本、置信度和引擎。 |
| ref_tick_x | 标签绑定的主尺刻线 x。 |
| extra_ticks | 从标签到零线额外计入的主尺刻线数。 |
| ocr_label_selection | left_of_zero 或 right_of_zero_minus_one。 |
| ocr_expanded_retry_used | 是否执行过上下扩框。 |
| ocr_long_tick_retry_used | 是否执行过长刻线锚点重试。 |
| ocr_reason | OCR 失败原因。 |

主尺 OCR 的典型失败原因如下。

| ocr_reason | 含义 | 优先检查 |
| --- | --- | --- |
| invalid_main_gap | 主尺刻线不足或间距无效。 | 主尺刻线和区域分离。 |
| missing_ocr_inputs | 缺主尺刻线、二值图或 zero_x。 | 游标零线和主尺阶段。 |
| no_digit_region | 无法按照零线与刻线几何生成 OCR 框。 | zero_x、main_gap、OCR 锚点。 |
| no_digit_component | 框内没有通过筛选的数字连通域。 | OCR 框 y 范围、数字粘连、ROI。 |
| ocr_no_digit | 有连通域但 OCR 引擎未给出有效数字。 | 模板/引擎、patch 和数字质量。 |
| no_ocr_digit_left_of_zero | 有 OCR 候选但不能按左右规则选中标签。 | 标签绑定刻线和零线位置。 |

## 7. 游标刻线、零线和小数读数

### 7.1 正式入口与基本原则

实现位于 caliper/vernier_scale.py 的 recognize_vernier_scale()。主流程不是强制寻找 51 条线，而是：

~~~text
区域分离给出的游标刻线带
  -> 横向投影与两侧有效谷底
  -> 谷底范围内的实测投影候选
  -> 连通域、上缘细笔画、周期结构筛选
  -> 每条刻线 x 精修
  -> 第一条接受刻线为 zero_x
  -> 与主尺线的离散最小误差对齐
~~~

如果上游二值图无效，游标模块先使用 VernierScaleConfig 的自适应阈值重建；若前景仍过少，则使用 Otsu。正常情况下复用预处理和区域分离传下来的二值图。

区域分离给出的 region_vernier.tick_band 会在下方额外加入 tick_band_bottom_pad=16 px，用来保留长游标刻线下端，避免连通域长度因刻线带底部裁切而失真。

### 7.2 投影、实测周期和谷底候选

在游标窄刻线带中逐列统计前景，得到归一化横向投影。预期周期优先由主尺间距给出：

~~~text
expected_gap = main_gap * 0.98
~~~

平滑窗口约为 expected_gap 的 0.25 倍，限制为 3 到 21 的奇数。谷底阈值由平滑投影中位数得到，并截断在 0.08 到 0.24：

~~~text
valley_threshold = clip(0.95 * median(smoothed_projection), 0.08, 0.24)
~~~

低响应连续段被合并后作为谷底候选。每对左右谷底之间必须至少覆盖约 8 个预期周期，且不得超过整条带的 92%，避免将太短的纹理或几乎整个背景误判为游标区域。

在候选谷底对之间，以“局部投影均值加 0.80 倍标准差，且最低为 0.02”的阈值提取连续投影峰段中心。随后由这些已观测 x 间隔估计 observed_period：先取相邻差的中位数，再保留 0.55 到 1.45 倍中位数内的间隔重算。它不是预先写死的理论游标周期。

### 7.3 谷底有效性与评分

每对谷底必须同时满足以下结构条件：

1. 左右谷底两边各有一到两个 observed_period 距离内的投影峰支撑。若谷底贴在边界、外侧平坦或只一侧有峰，会被拒绝。
2. 两谷底之间不存在长度达到 valley_internal_break_periods=1.3 个周期的大低响应断裂。短的刻线间间隙不会因此被拒绝。
3. 范围内必须得到足够多的投影候选，之后还必须通过候选去重、连通域和前缀筛选。
4. 周期清晰度、候选间距一致性、连通域/长度结构与谷底深度满足最小门槛。

候选总分为：

~~~text
total_score = 0.30 * valley_score
            + 0.30 * period_clarity
            + 0.25 * spacing_score
            + 0.15 * component_score

component_score = 0.35 * component_support
                + 0.50 * component_length_structure
                + 0.15 * projection_strength_structure
~~~

默认最低门槛如下。

| 参数 | 默认值 | 意义 |
| --- | ---: | --- |
| valley_min_period_clarity | 0.20 | 投影在一个实测周期位移后的相关清晰度下限。 |
| valley_min_total_score | 0.30 | 谷底对综合评分下限。 |
| valley_min_component_structure | 0.08 | 长短组件结构或投影强度结构下限。 |
| valley_peak_support_near_periods / far_periods | 1.0 / 2.0 | 谷底两侧峰支撑的近远搜索范围。 |
| valley_internal_break_periods | 1.3 | 内部低响应大断裂的最大周期长度。 |

若长度两类不明显，但所有候选都有很强的组件支持，代码存在一个保守回退：周期清晰度与总分通过且 component_support 不低于 0.75 时仍可接纳。这避免在刻线长度几乎一致的真实图像中把完整游标范围误判为空。

### 7.4 51 条的真实作用

config.vernier_scale.valley_preferred_tick_count 的默认值为 51，但它不是强制拟合条件。只有多个已通过结构门槛的谷底对总分差不超过 valley_score_tie_margin=0.02 时，才按“接受候选数离 51 的距离”进行二级排序：

~~~text
先比较总分是否在 0.02 以内
再优先 accepted_count 与 51 的绝对差更小者
最后才比较总分、周期清晰度、间距一致性
~~~

该规则不会新增候选、补齐空格或删除真实线。任何调参或论文描述都不应把它表述为“游标尺被强制拟合为 51 条”。

### 7.5 连通域、数字 0 干扰与候选去重

游标连通域为投影候选提供结构支持，但不是“没有独立连通域就一定不是刻线”的硬否决条件。当前处理如下。

1. 在每一列上桥接不超过 component_vertical_bridge_gap=10 px 的短纵向空白间隔。
2. 使用 component_vertical_open_height=7 的竖直开运算强调细直线。
3. 只保留接近刻线带上缘、足够高、足够细的组件。组件的顶部必须落在带高前约 1/4（同时限制为 8 至 18 px），最低高度为带高约 35%，组件宽度不超过实测周期的 75%。
4. 投影候选在约 0.42 个实测周期的半径内与组件一对一匹配，同一组件不会支持两个候选。
5. 对相距小于 duplicate_period_ratio=0.65 个周期的峰分组去重，优先保留有组件支持、投影强度更高、组件面积更大的候选。

打印的游标数字 0 有时会与真实零刻线相连，也有时会在零线左侧形成伪投影峰。当前算法对候选序列做“顶部细笔画”检查时，只丢弃最早一个具有上缘支持真实刻线之前的前缀伪候选；不会要求后续全部刻线都有同样的上缘细笔画。

如果真实零线被数字粘连而没有独立顶部细笔画，但其连通域在桥接后足够高，组件仍可提供替代证据。这个分支的目的就是避免将“零线与印刷 0 连为一体”的真实零线错误过滤掉。

### 7.6 刻线位置精修与零线定义

每个最终候选按以下规则建立刻线字典：

- 有匹配组件时，以组件靠近接缝的 x_near_seam 作为几何初值，同时保存组件下端 x、面积和高度。
- 没有匹配组件时，在投影候选附近半径为约 0.20 个实测周期、但被截断为 3 至 6 px 的小窗口内，只查看带顶部约 8 至 14 行的细笔画中心，中位数形成局部 x_refined；若该窗口没有可用细笔画，则退回投影 x。
- 对上述初值在灰度上缘窄带中调用 refine_tick_x_subpixel()，得到 x_precise。

投影初值、局部细化位置和亚像素位置会并存。

| 字段 | 意义 |
| --- | --- |
| x_projection | 投影峰段中心。 |
| x_refined | 连通域/局部细笔画精修后的初值。 |
| x_precise | 灰度边缘亚像素中心，正式对齐优先使用。 |

选中谷底范围内第一条最终接受的实测刻线定义为游标零线。之后会滤掉明显位于 zero_x 左侧的多余残留候选，再按 x 重新排序。零线错误通常优先检查谷底对、左侧前缀候选、组件图和顶部细笔画，而不是先修改最终对齐公式。

### 7.7 长短刻线分类、标准曲线与单线追踪

游标长短刻线分类使用当前图像中已支持组件的 component_bottom_y，而不是传给 _build_ticks_from_band_detection() 的 long_tick_factor。代码以 25/75 百分位作为两类初始中心，迭代按最近中心重分组，要求两类至少各有两个样本且相对分离度达到 long_cluster_min_separation_ratio=0.20。分离不足时保留刻线，但长短状态不作为可靠分类。

详细模式中的“长度归一化标准响应”对同一批已接受刻线再做两类长度聚类：短类显示幅值 1.0，长类显示 1.5；若样本不足或两类不分离，则显示单类。该图仅说明当前观察到的长度分布，不生成理论曲线。

详细模式还会逐条追踪候选刻线的中心线，并将每条线独立平移到自己的参考 x，生成“单刻线拉直”诊断投影。不同刻线允许不同斜率；此图不假设所有游标线共享一个方向。不过，这部分只有 make_debug=True 时生成，当前不回写 vernier_ticks、zero_x 或正式读数；它与正式路径中“无组件候选的小窗口顶部细笔画精修”是两条不同代码路径。

vernier_rectify.py 中的 _find_vernier_body_x_range() 仍被 roi_extract.py 用于主体 x 范围估计；rectify_vernier_region() 本身没有被 pipeline.py 调用，而且当前实现主要返回主体裁剪结果，尚未执行整块几何拉直。不要将该主体裁剪/校正研究结果或其他显示结果误认为已进入正式识别。

### 7.8 游标对齐与离散小数：find_best_alignment()

游标刻线按 x 从左到右排序。当前代码参与对齐的数量为：

~~~text
n = min(检测到的游标刻线数, round(1 / 0.02))
  = min(检测到的游标刻线数, 50)
~~~

对前 n 条中每一条，计算它与全部主尺刻线的最小横向绝对距离：

~~~text
error_i = min_j abs(vernier_x_precise[i] - main_x_precise[j])
best_index = argmin(error_i)
vernier_scale = best_index * 0.02
~~~

函数内部计算了游标 y 范围，但正式调用当前传入的是 None，因此实际对齐比较仍按横坐标完成，不施加 y 重叠过滤。这是当前实现边界，若要修改必须先为对齐索引语义补充回归测试。

best_index 邻域的抛物线插值得到 continuous_index，仅记录在 alignment_info 中；正式读数始终以 best_index 计算。对齐置信度由最优误差与相邻误差的相对突出程度给出，使用 config.vernier_scale 的 perfect、strong、moderate、weak、bad 分段阈值。

### 7.9 对齐歧义

当最优游标刻线与其直接相邻游标刻线的误差差值很小时，会生成 alignment_ambiguity。阈值为：

~~~text
threshold_px = clip(main_gap * 0.002, 0.05 px, 0.10 px)
~~~

歧义字典只保存最佳线和最佳相邻线，不在全局任取一个次优候选。merge_readings() 在不改变主读数的前提下补充：

~~~text
primary_total   = main_scale + primary_reading
reference_total = main_scale + reference_reading
~~~

GUI 将它显示为“推荐”和“参考”，详细模式的游标对齐图中也会显示相邻候选。人工判断两条线几乎同样对齐时可以参考该信息，但不应让 UI 自动替换 primary_total。

## 8. 读数合并、置信度和失败返回

### 8.1 merge_readings()

caliper/merger.py 的 merge_readings() 接收主尺刻线结果、游标刻线结果、旋转后的彩色 ROI、两套区域和 split_y。它执行的正式顺序为：

~~~text
取得游标离散小数和 zero_x
  -> 在 zero_x 已知条件下运行定向 OCR
  -> 推导 main_scale
  -> total = main_scale + vernier_scale
  -> 生成正式标注图与可选读数推导图
~~~

主尺 OCR 失败不抛出异常，main_scale 会返回 0.0，并把具体原因存入 main_derivation。主尺、游标或 OCR 的单个失败是否使 total 变为零，取决于其他部分是否仍返回数值；因此使用方应同时检查 main_derivation、vernier.error 和 result.extra_info 的 error，而不能只检查 total 是否为零。

### 8.2 置信度的实际计算

calc_confidence() 从 0.5 起算：

| 条件 | 加分 |
| --- | ---: |
| 主尺刻线数不少于 10 | 0.12 |
| 主尺刻线数不少于 5 但不足 10 | 0.06 |
| 游标刻线数与 1/precision 的比例 | 至多 0.20 |
| 主尺相邻间距变异系数小于 0.15 | 0.10 |
| 主尺相邻间距变异系数在 0.15 到 0.30 | 0.05 |

最终结果上限为 0.95。它没有使用 OCR 置信度、ROI 质量、谷底总分、对齐误差、人工标注或文件名真值，因此只能作为查看调试图的优先级提示。

### 8.3 常见失败返回

ROI 提取失败时，CaliperPipeline._fail() 返回：

~~~text
main_scale=0.0
vernier_scale=0.0
total=0.0
precision=0.02
confidence=0.0
extra_info.error = ROI 提取失败
~~~

游标阶段的空结果通常带有以下错误之一：

| 错误文本 | 含义 | 首先检查 |
| --- | --- | --- |
| no_reliable_valley_bounded_tick_range | 没有谷底对同时满足边界峰支撑、内部连续性和结构门槛。 | 游标带、谷底图、ROI 局部恢复。 |
| insufficient_vernier_tick_candidates | 已有谷底范围但最终接受刻线数不足。 | 投影候选、去重、连通域和顶部前缀筛选。 |

游标错误位于 pipeline.step_results 的 vernier 结果中。ROI 恢复仅对第一个错误类型尝试局部扩边。

## 9. 配置读取审计

caliper/config.py 集中声明了很多参数，但“已声明”不等于“当前正式运行会读取”。本表的口径为：

- 正式生效：当前 CaliperPipeline.run() 可达并影响正式候选或结果。
- 条件生效：只在输入二值图无效、失败恢复或显式开关打开时生效。
- 遗留/未读：仅被未调用旧函数读取，或全仓没有读取点。
- 形式读取：代码取到该值，但不会改变当前正式行为。

| 配置组 | 正式生效字段 | 条件生效字段 | 遗留、未读或形式读取字段 |
| --- | --- | --- | --- |
| PreprocessConfig | gamma、双边滤波、median_ksize、CLAHE、锐化、自适应阈值、adaptive_binary_scale | morph_open_*、cc_filter_*；默认关闭 | 无。前五个参数会在 Pipeline 构造时缓存。 |
| ROIExtractConfig | x_pad_ratio、y_pad_ratio、min_roi_height、min_roi_width | y_center_span_ratio 为初始 y 框；x_center_span_ratio 只用于 x 投影弱时的质心回退 | contour_*、score_weight_*、morph_kernel_ratio 未读。 |
| OrientConfig | angle_detection_scale | 无 | canny_*、hough_*、angle_*、trim_ratio、rotate_* 未读。 |
| RegionSplitConfig | 竖直开运算尺寸、组件尺寸限制、projection_use_components、seam_use_component_endpoints、平滑尺寸限制 | fallback_split_ratio、min_vernier_height_ratio 在端点/投影失败或高度不足时生效 | search_*、density_band_*、density_min_score、CLAHE、闭运算、梯度字段均无当前读取点。 |
| MainScaleConfig | peak_threshold_factor、min_tick_count、long_tick_factor、短线恢复四项 | adaptive_block_size、adaptive_C 仅上游二值图不可用时 | peak_min_dist 未进入当前主尺流程；spacing_* 仅供显式 `refine_ticks_by_spacing()` 研究调用，默认正式流程不读。 |
| VernierScaleConfig | 谷底评分/门槛、min_tick_count、刻线带余量、连通域桥接/开运算、候选去重、对齐置信度和歧义阈值、长度聚类分离度 | adaptive_block_size、adaptive_C 仅继承二值图无效时；recovery_min_observed_tick_count 仅 ROI 恢复接纳时 | long_tick_factor 被传入但不驱动当前游标长短分类，属于形式读取。 |
| OCRConfig | main_label_group_gap_ratio、patch_resize_factor、patch_clahe_clip、patch_adaptive_C、各 OCR 引擎参数 | Tesseract/EasyOCR 参数仅在相应引擎被选中时 | 全扫描强峰、旧搜索范围、旧连通域筛选、旧合并和旧几何回退字段仅作配置兼容保留，当前没有读取点；patch_adaptive_block 实际被按 patch 尺寸动态计算的 block 覆盖。 |
| MergerConfig | 无 | 无 | 所有字段目前没有正式读取点；最终绘图使用代码内颜色与现有逻辑。 |

调参前必须确认字段处于“正式生效”或“条件生效”列。直接修改遗留字段会造成“配置变了、结果完全不变”的假象。尤其不要根据 config.py 中的旧注释推断方向校正、区域分离和 OCR 的真实算法。

## 10. GUI、调试图与现场排查

### 10.1 GUI 行为

main.py 使用 Tkinter。默认勾选“快速模式”，通过后台线程运行 Pipeline，并由 progress_callback 更新右侧标签页。图像区域支持适应窗口、1:1、缩放、滚动和拖拽。

快速模式不会替换正式 ROI、刻线、OCR 或读数算法；它主要关闭详细可视化生成，并使用简化的最终标注。因此用于比较算法输出时，快速与详细模式的 total、zero_x 应保持一致。若二者不一致，应优先视为代码路径或状态复用问题，而不是正常模式差异。

详细模式中常见标签页如下。

| 标签页 | 产生位置 | 用于检查什么 |
| --- | --- | --- |
| 原图 | GUI 当前输入 | 原始拍摄质量和卡尺位置。 |
| ROI定位 | locate_roi_lowres() | ROI 是否覆盖数字、主尺、游标和接缝；紧凑框是否过小。 |
| 预处理 | preprocess() | 反光、数字粘连、二值前景是否使刻线消失或增生。 |
| 方向校正 | orient_caliper() | 接缝和刻线是否已被整体校正。 |
| 区域分离 | split_scales() | split_y、主尺/游标 tick_band 是否截断真实结构。 |
| 主尺刻线 | recognize_main_scale() | 主尺候选、短线恢复、长刻线和 main_gap 是否合理。 |
| 游标刻线 | recognize_vernier_scale() | 谷底、刻线带、投影、组件、标准曲线和单线追踪。 |
| 游标对齐 | Pipeline 重新绘制 | 最优游标线、主尺线、零线和相邻歧义候选。 |
| 主尺OCR | Pipeline 的 OCR 调试图 | 备用框、连通域、选中数字、零线和锚点。 |
| 最终标注 | merge_readings() | 所有正式证据在同一张图上的对应关系。 |
| 读数推导 | draw_reading_derivation() | 主尺整数、游标索引和总读数的推导。 |

快速模式不生成主尺、游标、OCR、对齐等详细调试面板；这不影响正式刻线和读数计算。

### 10.2 游标刻线页的组成

详细模式下，4b_游标刻度线 将多个证据纵向堆叠在一个页面内，而不是单独开谷底页面：

1. 检测用的窄游标刻线带，橙/黄线为候选，蓝线为零线。
2. 原始横向投影响应。
3. 候选所绑定组件的下端位置响应。
4. 长度归一化标准响应：短类幅值 1.0，长类幅值 1.5；无法稳定分成两类时为单类。
5. 单刻线追踪诊断：黄色为独立中心线，蓝点为接缝参考，红色 U 为未追踪的正式候选。
6. 谷底投影视图：显示平滑曲线、两侧谷底、阈值、刻线候选与零线。
7. 游标连通域视图：绿色为接受、橙色为拒绝、青色为未匹配的细长组件。

第 4 和第 5 项只用于界面展示，不能据此认定正式算法已经采用“标准曲线拟合”或“逐线校正”。

### 10.3 推荐排查顺序

~~~text
1. ROI定位：是否覆盖数字、零线、完整主尺/游标结构？
2. 区域分离：split_y 和两个 tick_band 是否正确？
3. 主尺刻线：main_gap、漏线、多线、长线恢复是否合理？
4. 游标刻线：两侧谷底是否夹住完整游标，首条是否真实 0 线？
5. 游标对齐：最小误差线和相邻参考线是否符合图像？
6. 主尺OCR：候选框、字符连通域、字符组合、绑定主尺线是否正确？
7. 读数推导：main_scale + vernier_scale 是否与标注索引一致？
~~~

不要从最终 total 直接修改某个阈值。比如整数部分偏 1 既可能是 zero_x 偏移，也可能是 OCR 标签选择或主尺刻线计数；必须先定位第一处图像证据异常。

### 10.4 常见诊断字段

| 位置 | 字段/错误 | 首先检查 |
| --- | --- | --- |
| result.extra_info | error = ROI 提取失败 | 输入图、低清投影、ROI 最小尺寸。 |
| pipeline.step_results 的 vernier | no_reliable_valley_bounded_tick_range | 游标带、两侧谷底峰支撑、内部大断裂、ROI 局部恢复记录。 |
| 同上 | insufficient_vernier_tick_candidates | 谷底范围、候选去重、连通域与顶部前缀。 |
| result.extra_info 的 main_derivation | invalid_main_gap 或 missing_ocr_inputs | 主尺刻线、分割与 zero_x。 |
| 同上 | no_digit_region、no_digit_component、ocr_no_digit | OCR 框、连通域、ROI 和 OCR 引擎。 |
| 同上 | no_ocr_digit_left_of_zero | 数字绑定的主尺线和零线左右关系。 |
| result.extra_info | alignment_ambiguity 非空 | 游标对齐图中的正式线与 ALT 相邻线。 |

## 12. 已知局限与维护规则

### 12.1 已知局限

1. ROI 依赖低清投影、近似等间距刻线和卡尺主体边缘。紧凑框的结构验证只确认左侧参考和竖直支持存在，并不证明两套刻线及数字都完整；背景中存在密集竖纹、刻线带被遮挡或主体边缘不清晰时，紧凑框可能过大、过小或偏移。
2. 方向校正只拟合一条全局接缝线。单条游标刻线因透视产生不同斜率时，正式读数不会进行逐线几何校正；逐刻线校正函数仅用于详细模式研究和诊断，尚未回写正式读数。接缝种子会优先使用刻线带谷底动态估计，失败时再使用经 15 px 去重后的固定高度候选。
3. 区域分离优先依赖细长竖直组件端点；主尺刻线过短、游标刻线带过淡或接缝附近有干扰时，可能回退到投影谷底或物理比例，影响后续 tick_band。
4. 游标零线定义为选中谷底范围中的第一条最终接受刻线。左谷底选错、数字 0 造成前缀、真实零线断裂，都会直接造成整数和小数的级联偏差。
5. 主尺 OCR 的字符候选连通域阈值部分硬编码，且多位数仅支持 10 到 15。模板库覆盖不足、字体变化、数字粘连或 OCR 框偏移时，主尺整数可能缺失或错误。
6. 正式游标对齐当前只比较横坐标，并只比较排序后前 50 条游标刻线；这是现有实现的明确边界。
7. confidence 是启发式分数，不能代替经标定的成功概率、误差上界或工业质量判定阈值。
8. config.py 中仍有兼容字段和未读字段；只改参数文件而没有调用链审计，很容易得到“配置变了、结果不变”的无效调参结论。

### 12.2 推荐维护顺序

当新增样本或修复错误时，按以下顺序工作：

1. 保存原图、详细模式的各阶段图和最终 extra_info，先确认错误第一次出现的阶段。
2. ROI 问题优先检查候选框是否漏掉数字、主尺/游标端部或带入过多背景；不要先调整 OCR。
3. 分割问题优先检查组件端点和 tick_band；不要只看 split_y 的一条线。
4. 游标问题先检查谷底两侧峰支撑、内部断裂和零线前缀，再检查连通域和对齐。
5. OCR 问题先检查零线、主尺刻线和候选框 y 锚点，再检查字符连通域与 OCR 引擎。
6. 修改正式阈值前，在 tupian 上比较改动前后批评估，并单独保存可视化。只修复一张图却明显伤害其他图像的改动不应直接采用。
7. 若要把显示专用的长度聚类、单线追踪或 vernier_rectify.py 引入正式读数，先新增独立开关、定义输入输出、写失败测试和回归集，再接入流水线。

### 12.3 不应采用的捷径

- 不从图片文件名回填正式读数。
- 不把缺失主尺/游标线按理论等距直接生成后用于读数。
- 不强制游标检测必须等于 51 条；当前的 51 仅是近似同分谷底候选的二级偏好。
- 不把 continuous_index 写回 vernier_scale。
- 不把批评估的 suspected_error_module 当作人工确认根因。
- 不根据 config.py 的旧注释判断某字段是否有效，先搜索其实际读取点。

## 13. 标准化曲线与研究接口

### 13.1 统一结果契约

详细模式的主尺和游标尺都输出 `standardization` 字典：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `int` | 当前契约版本，现为 `1`。 |
| `width` | `int` | 曲线坐标域宽度，所有曲线数组均为该长度。 |
| `x_offset` | `int` | 局部曲线坐标映射到父级旋转 ROI 的横向偏移。 |
| `curves.raw_projection` | `float[]` | 原始竖直投影，非有限值被置零。 |
| `curves.support` | `float[]` | 刻线来自图像证据的支撑响应。 |
| `curves.normalized_response` | `float[]` | 以已接受刻线为中心生成的显示响应。 |
| `ticks` | `dict[]` | 一条记录对应一条已接受刻线，不包含候选补线。 |
| `classification` | `dict` | `mode`、`centers`、`counts`、`separation`、`threshold`。 |

主尺标准化使用主尺 ROI 坐标，`raw_projection` 是主尺竖直投影，`support` 是刻线横坐标 ±2 像素窗口的最大接缝侧支撑。游标标准化使用检测带坐标，`raw_projection` 读取 `vernier_band_detection['proj_norm']`，`support` 读取每个连通域的 `component_bottom_y`，因此可同时查看投影、连通域下端和长度响应。

### 13.2 游标长度聚类

`_build_length_clustered_standard_response(width, ticks, x_offset)` 保留历史返回字段 `mode`、`cluster_centers`、`cluster_counts`，并增加统一别名 `classification_mode`、`centers`、`counts`、`separation`、`threshold`。算法仅对观测到的 `length` 做一维聚类：有效刻线少于 6 条时不分两类；达到数量后按 5%/95% 分位截断极端值，以 25%/75% 分位初始化中心并迭代；只有两簇各不少于 3 条且中心差达到 `max(2 px, 0.20 × 截断长度中位数)` 才使用 `two_clusters`。显示振幅固定为短线 `1.0`、长线 `1.5`，不是毫米读数，也不补齐缺失刻线。

游标详细模式在完成零线前的正式刻线清理后调用 `_build_vernier_standardization()`，并把同一个对象挂到 `step_results['vernier']['standardization']` 与 `step_results['vernier']['vernier_band_detection']['standardization']`。`_draw_vernier_ticks_on_band()` 只读取这个对象绘制原始投影、支撑曲线和归一化曲线，避免 UI 与结果结构各自计算。快速模式、空结果和没有可靠候选的样本均返回 `standardization=None`。

### 13.3 样例导出

`tools/export_standardization_samples.py` 使用 `np.fromfile`/`cv2.imdecode` 读取中文路径，运行 `CaliperPipeline(fast_mode=False)`，保存现有 `3a_主尺刻度线` 与 `4b_游标刻度线` 详细面板，并写出 UTF-8 `standardization_summary.json`。示例：

```powershell
python tools/export_standardization_samples.py --input-dir tupian --output-dir debug_tupian_standardization_20260814 --image 30.00.jpg --image 120.60.jpg --image 72.52.jpg --image 130.70.jpg --image 40.20.jpg --image 140.00.jpg
```

摘要只记录实际运行得到的读数、分类、曲线宽度和接受刻线数，不把文件名真值传入算法。本轮 `40.20.jpg` 的游标标准化为空，原因是正式前置分割没有形成可靠游标候选；这类失败必须保留为空，不能用理论曲线替代。

## 14. 维护者快速检查表

在提交任何算法修改前，至少能回答下列问题：

~~~text
[ ] 改动影响的是 ROI、方向、分割、主尺、游标、OCR 还是仅调试显示？
[ ] 该参数/函数是否由 CaliperPipeline.run() 的正式路径读取？
[ ] 失败样本的第一处错误证据出现在哪个调试页？
[ ] 改动是否会改变已观测刻线数量、zero_x、main_gap 或 OCR 候选框？
[ ] 是否保留了“无图像证据不补线、不读取文件名”的约束？
[ ] 是否运行了对应 pytest 回归和至少一次批评估对比？
[ ] 是否把新的可视化图与结果 JSON 一起保留，以便复核？
~~~

当这份检查表无法回答时，优先补充诊断数据和测试，而不是继续叠加阈值。对本项目而言，可靠读数来自可追溯的图像证据链，而不是某一张图片上碰巧接近真值的输出。
